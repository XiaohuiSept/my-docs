# CICD 本期产品需求文档

## 一、背景与目标

### 1.1 Roadmap 阶段与版本范围

本 PRD 对应 CICD Roadmap 的“本期 MVP”阶段。源文档未给出正式版本号、开发起止日期和上线日期，均暂标为待确认；本 PRD 使用相对里程碑描述交付节奏。

本期在 Global Console 中交付一条可验收的端到端链路：平台管理员接入执行资源并投放给租户，租户管理员组织项目和授权，业务用户从受信任模板创建流水线，完成测试、构建、镜像推送，并将应用部署到获授权的目标环境。

### 1.2 要解决的核心问题

当前需要把执行资源、权限、流水线构建和应用部署统一到 Global 管理面，解决以下问题：

1. 执行资源、构建能力和部署目标缺少统一接入与可用性判断。
2. 流水线、运行记录、日志、制品和应用部署需要按租户、项目和角色隔离。
3. 用户需要在不接触 Tekton 原生对象和凭证明文的情况下完成可追溯构建。
4. 构建结果需要以不可变镜像和固定版本进入受控 Direct CD，并能查询部署结果和历史。
5. Runner 失联、重复触发、取消、重启和归档等异常必须有明确状态，避免重复执行和越权读取。

### 1.3 成功判据与指标

本期硬性成功判据：

- 普通用户可完成“模板实例化 → 构建 → 镜像产出 → 测试环境部署 → 查看日志和结果”的订单服务主路径。
- 同租户跨项目、跨租户和无对应角色的读取、运行、部署请求被拒绝。
- 每次 PipelineRun 和 DeploymentRun 均保存不可变输入、稳定 UID、版本、目标和执行关联。
- 运行下发结果未知、目标失联或 Controller 重启时，不产生未经核实的重复执行。
- Helm OCI、Git YAML、Git Kustomize 三类应用来源均可完成固定版本获取、部署和就绪检查。

以下目标需在需求冻结前补齐：API 响应时间、最大并发、可用性、错误率、日志延迟、历史保留周期和业务采用率。未补齐前只能作为待确认项，不能作为已承诺 SLO。

| 灰度/试点上线 | 待确认 | 试点验收记录、监控看板、告警和回滚预案 | 试点租户完成主路径，数据和权限无越权 |

### 2.2 不可发布条件

出现以下任一情况，必须延期或回滚：

- 核心构建或部署链路不能完成，或构建失败错误地触发 CD。
- 跨项目/跨租户数据、日志、制品或历史记录越权。
- 凭证明文进入日志、快照、结果、API 响应或前端展示。
- 下发结果未知时可以直接换 Runner、重建同名对象或重复部署。
- 目标集群、Namespace、资源类型或凭证权限校验失效。
- 历史、日志、审计或制品在归档后不可查询或查询越权。
- 离线环境无法完成模板获取、构建推送、日志和历史查询。
- 升级、数据迁移、兼容矩阵或回滚验证失败。

## 三、产品概述

### 3.1 一句话定义

CICD 是部署在 Global Console 的多租户交付服务：管理员准备受控执行资源和权限，用户基于受信任模板构建不可变镜像，并将应用以 Direct CD 方式发布到获授权目标。

### 3.2 功能列表

| 模块 | 功能点 | 优先级 |
| --- | --- | --- |
| 安装与资源准备 | 服务启停、Runner 接入/校验、构建池、部署池、代码源、Harbor、凭证、离线验证 | 核心 |
| 权限与隔离 | 租户投放、项目归属、角色授权、资源使用权、撤权、审计、Namespace 隔离 | 核心 |
| 模板中心 | Task/Pipeline 目录、版本发布/停用、验证状态、实例化 | 核心 |
| 流水线定义 | Pipeline 创建、编辑、删除、图形/YAML 双向编辑、DAG 和参数校验 | 核心 |
| 构建运行 | 手动/Webhook、排队、单 Runner 执行、取消、重跑、状态同步、历史、日志、结果、制品 | 核心 |
| 应用交付 | Application 定义、Helm/YAML/Kustomize、镜像绑定、DeploymentRun、就绪检查、历史、重新发布 | 核心 |
| 治理与清理 | 运行归档、日志归档、保留和清理、审计 | 非核心但本期交付 |
| 编辑体验 | 图形布局保存、运行视图按快照叠加状态 | 非核心但本期交付 |

### 3.3 本期明确不包含

GitOps、持续健康监控、漂移修复、自动回滚、应用卸载与自动清理、灰度/渐进式发布、定时触发、通知中心、收藏、完整应用商店、任意 Tekton YAML 导入、普通用户发布任意 Task、跨 Runner 拆分执行、失败任务续跑、普通构建脚本读取生产凭证、通用自动 prune、审批流和任意应用 Hook。

## 四、目标用户与核心使用场景

### 4.1 用户角色

| 角色 | 主要任务 | 本期权限边界 |
| --- | --- | --- |
| 全局管理员 | 启停服务、接入 Runner、配置构建池/部署池、向租户投放资源 | 平台级配置；跨租户操作必须审计 |
| 租户管理员 | 组织项目、用户组、资源范围和 Policy | 只能在已投放资源范围内授权 |
| 项目管理员 | 管理项目流水线、触发和应用配置 | 不自动获得平台资源或凭证维护权 |
| 项目编辑者 | 创建、修改、删除 Pipeline/Application | 编辑权与运行权分离 |
| 项目运行者 | 运行、取消本人运行、重新运行旧版本 | 只能提交产品允许的参数 |
| 项目查看者 | 查看定义、运行状态及被授予的日志/结果/制品 | 不能创建、编辑、运行或部署 |

### 4.2 核心场景

本版本只聚焦一个核心任务：让被授权的业务用户将一份受信任的代码变更可靠地构建为不可变镜像，并发布到一个被授权的应用目标。

主路径：

1. 全局管理员启用 CICD，接入并校验 Runner，配置构建池和部署池。
2. 全局管理员向租户投放服务和资源；租户管理员将资源组织到项目并授权。
3. 业务用户从模板中心实例化 Pipeline，选择代码源、构建池和凭证引用。
4. 用户手动运行或由已验签 Git Webhook 触发；服务端冻结 Commit、参数、Task Digest、权限和执行策略。
5. Controller 选择一个可用 Runner，Tekton 执行测试、构建、推送和扫描。
6. CI 成功后，用户或关联配置创建独立 DeploymentRun；Runner 固定部署版本和镜像 Digest，部署到授权 Target。
7. 用户查询构建/CD 状态、日志、结果、制品、资源清单和历史。

## 五、需求范围说明

### 5.1 包含范围

- Global 管理面中的服务、Runner、资源池和第三方资源准备。
- Nexus User、Group、Role、Policy 和 ResourceNode 作为授权来源。
- 版本化受信任 Task/Pipeline 模板及实例化后的产品 Pipeline。
- Pipeline 的定义、触发、运行、取消、重跑、日志、结果、制品和历史。
- Application、DeploymentRun 以及 Helm OCI、Git YAML、Git Kustomize Direct CD。
- 运行和部署的不可变快照、稳定 UID、归档、清理和审计。

### 5.2 不包含范围

| 不包含项 | 原因 |
| --- | --- |
| GitOps、持续健康、漂移修复 | 不属于 Direct CD MVP |
| 自动回滚、灰度发布、审批 | 需要额外策略和状态模型，后续规划 |
| 应用卸载、自动 prune、自动清理 | 可能产生不可逆目标副作用，本期不处理 |
| 定时触发、通知中心、收藏 | 不影响核心构建到部署链路 |
| 任意 Tekton YAML、任意 Task、普通用户自定义执行身份 | 与受信任模板和安全边界冲突 |
| 跨 Runner 拆分、失败任务续跑 | 本期一次运行固定一个 Runner |

### 5.3 系统和团队边界

- Global/Nexus：认证、可信租户上下文、服务入口、ResourceNode、Policy、角色与平台集群接入。
- CICD API/Controller：产品鉴权、资源模型、快照、排队、调度、下发、状态同步、归档和查询。
- Runner/Tekton：执行受信任 Task，访问代码源、Harbor、Results、日志和 Target。
- Harbor/代码源/Target：提供受管制品、源码、部署目标和凭证引用。
- PostgreSQL/OpenSearch/Results：分别承载产品历史、日志和原生运行归档。

平台契约未冻结的部分列入第八章待澄清项，不作为客户端自行猜测的行为。

## 六、详细需求说明

### 6.1 安装与资源准备

#### 6.1.1 服务启停与健康

**需求描述**：全局管理员在 Global 服务目录中启用或禁用 CICD，查看版本、依赖和健康状态。

**交互流程**：

1. 进入“平台管理 → 服务管理 → CICD”。
2. 页面展示启用状态、服务版本、依赖组件状态、最近检查时间和失败原因。
3. 点击“启用”后，系统校验 Global 管理面、数据库、日志和 Harbor 配置；通过后置为“已启用”。
4. 点击“禁用”后，阻止新的创建、运行和部署请求；活跃运行继续被追踪，页面展示“禁用中/已禁用”。
5. 启用或禁用失败时保留原状态，显示可操作的失败原因和重试入口。

**业务逻辑与规则**：仅全局管理员可操作；禁用不删除投放、授权、历史和活跃运行；服务状态由服务端返回，前端不得仅凭按钮状态判断成功。

**边界与异常**：依赖不可用时禁止启用；Global 不可用时已下发任务继续执行，但创建、取消和查询返回服务不可用并保留可恢复状态。

**验收标准**：

- Given CICD 依赖完整且用户为全局管理员，When 点击启用并检查完成，Then 状态为“已启用”，新请求可进入。
- Given 服务已启用，When 非全局管理员调用启停接口，Then 返回无权限且状态不变。
- Given 存在活跃运行，When 禁用服务，Then 新运行被拒绝，活跃运行仍可查询。

#### 6.1.2 Runner 接入、安装与校验

**需求描述**：全局管理员选择受管集群接入 Runner，安装或复用兼容 Tekton 组件，并将通过试运行的集群开放为可调度 Runner。

**交互流程**：

1. 进入“接入与资源准备 → Runner”。
2. 选择 Region、集群稳定 ID 和受支持发行版本，提交接入。
3. 系统检查集群身份、安装权限、现有 Tekton 版本、CRD、Webhook、Controller、Bundle Resolver、Results、存储和网络。
4. 未安装或兼容时调用平台安装机制；重复接入复用已有安装，不重复创建组件。
5. 安装完成后执行 Bundle 拉取、试运行、Results 归档和日志查询验证。
6. 状态按“待准备、准备中、可用、异常、停止接单”展示；只有“可用”进入调度集合。

**业务逻辑与规则**：集群按稳定 UID 绑定；Host 和 Member 集群均可接入；组件版本必须在支持矩阵内；不兼容或试运行失败的 Runner 不得接收新运行。

**边界与异常**：安装中断保留失败阶段和原因，可重试；安装结果未知时先查询已有组件，不得直接重复安装；无权限集群拒绝接入。

**验收标准**：

- Given 已存在兼容 Runner，When 再次提交相同集群接入，Then 不重复安装，返回原接入记录。
- Given Tekton 版本不兼容，When 提交接入，Then 状态为异常且该集群不可调度。
- Given 试运行未同时通过执行、归档和日志校验，When 查询 Runner，Then 不显示为可用。

#### 6.1.3 构建池、部署池与第三方资源

**需求描述**：管理员配置可被项目引用的构建能力、部署目标、代码源、Harbor 和凭证引用。

**交互流程**：

1. 在“构建池”中填写集群范围、Region、能力、架构、StorageClass、Namespace 策略、最大并发和是否接单。
2. 在“部署池”中填写 Target 集群、Namespace、允许的资源类型/操作范围和部署凭证引用，并执行连通性检查。
3. 在“第三方资源”中登记 Git/Harbor 地址、允许路径或项目范围和受管凭证引用。
4. 页面仅展示凭证名称、用途、状态和最后校验时间，不展示密钥。
5. 修改池范围、并发或停止接单后，服务端返回新版本和生效状态。

**业务逻辑与规则**：构建池和部署池使用权分别授权；池并发上限与租户/项目配额共同限制运行准入；停止接单只阻止新运行，已下发运行继续可追踪；凭证按源码拉取、镜像推送、CD 获取、Target 访问和业务 Pod 拉取用途隔离。

**边界与异常**：连通性或凭证校验失败不得标记可用；缩小部署池范围后阻止新的越界执行，已有运行保留快照；容量未知时进入排队或异常，不擅自换池。

**验收标准**：

- Given 用户只有构建池使用权，When 请求部署池目标，Then 部署请求被拒绝。
- Given 构建池已停止接单，When 新运行提交，Then 运行进入明确拒绝或排队状态；已运行任务仍可查询。
- Given 连接校验成功，When 查询资源详情，Then 返回元数据和状态，不返回凭证明文。

#### 6.1.4 离线环境

**需求描述**：离线安装能够从内网仓库获取 Chart、镜像、Task Bundle、模板和依赖，完成构建、日志和历史查询。

**规则与验收**：安装配置内网地址、自定义 CA 和受管凭证；所有资产校验版本、Digest、架构和 Catalog 对应关系。Given 无公网访问，When 执行订单服务主路径，Then 模板、工具镜像、构建推送、Results、日志和历史均从内网完成；任一资产缺失时显示具体资产和阶段，不回退公网或可变地址。

### 6.2 权限与隔离

#### 6.2.1 资源归属与角色

**需求描述**：每个 Pipeline、PipelineRun、Application 和 DeploymentRun 绑定一个 Tenant 和唯一 ResourceNode；用户通过 Nexus Policy 获得具体动作权限。

**交互流程**：

1. 用户进入项目后，列表只返回其有效 Policy 覆盖的资源。
2. 创建资源时选择项目/子项目；服务端从可信租户上下文确定 Tenant，写入节点 UID、创建者和存储 Namespace。
3. 租户管理员为用户或 Group 绑定查看、编辑、运行、日志、制品、部署和凭证使用动作。
4. 服务端对每个引用资源分别检查权限；页面隐藏无权操作，API 仍必须拒绝越权请求。

**规则**：ResourceNode 授权覆盖节点及后代；全部有效 Allow Policy 取并集；节点名称和创建者不产生隐含权限；跨项目共享仅共享业务对象访问，仍使用原项目的池、配额和凭证范围；跨租户共享不在本期。

**验收标准**：

- Given `order-team` 用户被授予查看权，When 查询 `payment-team` Pipeline，Then 列表和详情均不可见。
- Given 用户只有编辑权，When 运行 Pipeline，Then 返回无运行权限。
- Given 运行者未获部署目标和凭证使用权，When 创建 DeploymentRun，Then 返回对应资源的无权限错误。

#### 6.2.2 撤权、审计与后端隔离

**需求描述**：撤销权限后阻止新的读取和执行，并保留历史原归属与审计记录。

**规则与异常**：API 每次读取列表、详情、日志、结果和制品均重新按资源 UID 鉴权；运行下发前和部署写入前二次鉴权；撤权后的已下发运行进入取消/未知核对流程，不直接删除记录；审计记录主体、租户、项目、动作、对象、目标、结果和请求关联，不记录密钥。

**验收标准**：

- Given 用户撤销日志读取权，When 请求新日志游标或下载链接，Then 返回无权限，不能使用旧链接绕过鉴权。
- Given 历史资源原属 `order-team`，When 同名 Pipeline 在另一项目重建，Then 旧历史仍绑定原 UID 和授权范围。
- Given 运行已下发，When 用户被撤权，Then 系统拒绝新的下发并记录撤权审计，运行状态继续可核对。

### 6.3 模板、流水线与构建运行

#### 6.3.1 模板目录、版本与实例化

**需求描述**：用户浏览获授权的 Task/Pipeline 模板，选择固定版本实例化为独立 Pipeline。

**交互流程**：

1. 进入“模板中心”，按类型、语言、验证状态和版本查看模板。
2. 打开模板详情，查看输入、Task 契约、Result/Workspace、能力要求、架构、离线支持和摘要。
3. 点击“实例化”，填写开放输入，如代码源、构建池、Git 凭证和 Harbor 凭证。
4. 系统校验输入权限、类型、必填项和资源范围；成功后创建独立 Pipeline，保存模板 ID、版本和内容摘要。
5. 模板后续发布新版本不修改已实例化 Pipeline；停用版本阻止新使用，保留历史；安全撤销可阻断策略。

**规则**：普通用户只能组合受信任 Task 和契约允许的参数；不能上传任意 Tekton YAML、TaskSpec、ServiceAccount、PodTemplate 或明文凭证。

**异常**：模板版本不可见、停用、摘要不匹配或引用资源无权时拒绝实例化，并按字段返回原因；不静默替换版本。

**验收标准**：

- Given 用户有模板查看但无实例化权，When 提交实例化，Then 返回无权限。
- Given 模板开放输入缺失或类型错误，When 提交实例化，Then 返回字段级错误且不创建 Pipeline。
- Given 模板发布新版本，When 查询已有 Pipeline，Then 其编排和来源摘要不变。

#### 6.3.2 Pipeline 定义与图形/YAML 双向编辑

**需求描述**：用户创建和维护产品 Pipeline，可在图形编辑器与产品 YAML 间切换，且两者使用同一份语义定义。

**交互流程**：

1. 进入项目“流水线”，选择模板实例或新建 Pipeline。
2. 在图形模式添加 Stage/Task、连接依赖、填写参数和凭证引用；节点使用稳定 Task ID。
3. 切换 YAML 模式编辑产品 Schema；保存前解析并校验。
4. 保存时服务端检查 Task 版本、参数类型、上游存在性、循环依赖、Result 引用、资源权限和版本号。
5. 图形布局坐标和折叠状态作为独立 UI 元数据保存；缺失时自动布局，不进入执行快照。
6. 并发保存携带 `resourceVersion`；冲突返回 409 并保留服务端版本供用户合并。

**规则**：图形节点对应 `stages[].tasks[].id`，连线对应 `runAfter`，Result 引用同时形成数据依赖；未知字段、任意 Tekton YAML 或不支持节点必须字段级报错并保留原文，禁止静默丢字段。

**验收标准**：

- Given Pipeline 含稳定 Task ID 和依赖，When 图形转 YAML 再转图形，Then 任务、参数类型、依赖和引用语义不变。
- Given 两个用户基于同一版本保存，When 第二次保存时版本已变化，Then 返回 409 且不覆盖第一次修改。
- Given DAG 存在环路或未知 Task，When 保存，Then 返回字段级错误且不进入可运行状态。

#### 6.3.3 运行触发与输入冻结

**需求描述**：用户手动或通过 Git Webhook 触发 Pipeline，服务端在创建运行前固定所有执行输入。

**交互流程**：

1. 用户在 Pipeline 详情点击“运行”，选择已允许的分支/Commit 和参数；或 Webhook 入口接收事件。
2. API 验证可信身份、项目归属、运行权限、代码源、池、凭证和参数。
3. Webhook 校验签名、事件类型、分支过滤和主体绑定；事件按主体、Pipeline、规则和请求标识去重。
4. 服务端解析完整 Commit，调用编译校验，固定 Task Bundle Digest、Pipeline Generation、参数、权限、池策略和触发身份。
5. 完整快照持久化成功后返回运行 ID 和状态“排队”；同一幂等键同内容返回已有运行，不同内容返回 409。

**规则**：客户端不能提交快照、执行身份、已授权标记或原生 Tekton 对象；运行 `spec` 创建后不可变；分支和 Catalog 后续变化不影响该运行。

**验收标准**：

- Given 同一幂等键和同一内容，When 重复提交，Then 只产生一条 PipelineRun 并返回同一 ID。
- Given 同一幂等键但参数不同，When 提交，Then 返回 409，不产生第二条运行。
- Given Webhook 签名无效或主体无运行权，When 接收事件，Then 拒绝且不创建运行。

#### 6.3.4 排队、Runner 选择与下发

**需求描述**：Controller 根据权限、能力、架构、容量、配额和安全要求选择一个可用 Runner 并下发原生执行。

**规则**：一次原生执行固定一个 Runner；使用原子容量预留；未知执行继续占用容量；下发对象使用产品运行稳定身份生成的固定名称和 UID 关联，禁止 `generateName` 代替幂等。

**交互与状态**：运行依次展示“排队、下发中、运行、成功/失败、取消中、已取消、超时”；连接异常、结果未知和最后确认时间作为独立状态条件显示。

**异常处理**：无可用容量进入排队；配置/权限错误直接失败；创建结果超时时先在原 Runner 按稳定名称和 UID 核实，确认前禁止换 Runner 或重建。

**验收标准**：

- Given 两个 Runner 均可用，When 运行被绑定到其中一个，Then 后续重试和状态同步只使用该 Runner。
- Given 池容量已满，When 新运行提交，Then 进入排队且不创建原生 PipelineRun。
- Given 下发响应超时，When Controller 重试调谐，Then 先核实原对象，不产生重复原生运行。

#### 6.3.5 取消、重跑、重启恢复与清理

**需求描述**：用户可以取消允许范围内的运行、对已终止运行重新运行，Controller 重启后能继续观察；清理前保护未终止或未归档对象。

**规则**：取消先保存意图，再通知 Tekton，确认停止后标记“已取消”；重跑创建新记录并重新鉴权，未知旧运行必须先确认停止；Controller 重启根据产品快照和原生 UID 恢复观察；清理前确认执行终止、历史归档、制品保存、日志完成或缺口已记录。

**验收标准**：

- Given 运行仍在执行，When 用户点击取消，Then 状态先为“取消中”，确认原生执行停止后才为“已取消”。
- Given 运行结果未知，When 用户点击重跑，Then 系统拒绝派发并要求完成旧运行核对。
- Given 运行已归档且日志完成，When 到达保留期，Then 产品记录和临时执行资源按策略幂等清理，历史授权查询仍可用。

#### 6.3.6 日志、结果、制品与历史

**需求描述**：用户按授权查看运行状态、任务状态、结构化 Result、制品引用和流式日志。

**交互流程**：

1. 在运行详情查看阶段、Task、Step、状态、开始/结束时间、Runner 和数据新鲜度。
2. 点击日志，按 Task/Step/流类型查询；采集中返回已有数据，并显示采集状态和最后游标。
3. 使用服务端游标继续查询；游标绑定用户授权、运行和筛选条件并有有效期。
4. 在结果/制品页查看镜像 Digest、报告和制品 URI；禁止从日志文本猜解析构建结果。
5. 终态后从产品历史库和 OpenSearch 查询，原生对象清理后仍按产品运行 UID 查询。

**规则**：列表和详情按 Tenant/节点/资源 UID 过滤；日志状态包括 `Collecting`、`Complete`、`Gap`、`Expired`；归档和日志完成分别记录；索引不可用返回 503，不伪造完整日志。

**验收标准**：

- Given 用户有运行查看权但无日志读取权，When 打开运行详情，Then 可见状态但日志入口和接口均拒绝。
- Given 日志仍在采集，When 查询日志，Then 返回已有条目、`complete=false` 和下一游标。
- Given 原生 Pod 已清理且产品归档完成，When 查询历史和日志，Then 返回归档数据并按当前权限过滤。

### 6.4 应用交付

#### 6.4.1 Application 定义

**需求描述**：项目用户保存可复用应用来源、默认版本、镜像绑定和允许覆盖参数。

**交互流程**：

1. 进入项目“应用交付 → 应用”，点击新建。
2. 选择 `Helm`、`YAML` 或 `Kustomize`；填写 Harbor OCI 或 Git 地址、根路径、源凭证引用和默认版本。
3. 配置镜像绑定：Helm 使用明确 values 路径，YAML 使用工作负载/容器定位，Kustomize 使用镜像名。
4. 配置允许覆盖字段及类型/范围；保存时校验来源组合、路径、凭证、绑定和项目归属。
5. Application 更新只影响后续 DeploymentRun，已有运行保留完整定义快照。

**验收标准**：

- Given 来源类型和地址组合不受支持，When 保存 Application，Then 返回字段级错误且不创建。
- Given 镜像绑定缺失或存在多个歧义匹配，When 发布，Then 发布前拒绝，不做全局字符串替换。
- Given Application 已更新，When 查看已存在 DeploymentRun，Then 其快照和实际版本不变。

#### 6.4.2 DeploymentRun 创建与输入冻结

**需求描述**：用户从 Application 发起一次独立部署，或由 CI 成功事件按关联配置发起；服务端冻结应用、配置版本、镜像、目标和参数。

**交互流程**：

1. 用户选择 Application、部署版本覆盖（可选）、镜像引用、部署池、Cluster、Namespace、releaseName 和允许覆盖项。
2. API 检查应用、目标、凭证、部署池、镜像仓库范围和当前主体权限。
3. 未提供版本覆盖时使用 Application 默认版本；两者均缺失时拒绝。
4. 将 tag/branch 解析为 OCI Digest/Git Commit，镜像解析为 `repository@sha256:...`。
5. 保存 Application UID/Generation、完整 spec 快照、固定来源版本、镜像 Digest、Target、可信主体和幂等键，状态进入“排队”。
6. CI 触发时必须是已成功、已验证且匹配关联配置的 CI 运行；构建失败、取消或未确认状态不得触发 CD。

**验收标准**：

- Given 用户无目标 Namespace 部署权，When 创建 DeploymentRun，Then 写入前拒绝。
- Given CI 运行失败，When Controller 处理终态，Then 不创建 DeploymentRun。
- Given 同一 CI UID、部署节点和目标重复到达，When 处理事件，Then 复用同一 DeploymentRun，不重复写入目标。

#### 6.4.3 获取、渲染、部署与就绪检查

**需求描述**：受信任 CD Task 获取固定版本内容，绑定镜像，校验资源范围，在目标实例锁内部署并检查就绪。

**交互流程**：

1. Runner 使用对应源凭证获取固定 Chart 或 Git Commit；禁止 `latest` 和可变远程依赖。
2. Helm 按 values 路径绑定镜像；YAML 按工作负载/容器字段替换；Kustomize 生成固定清单后绑定镜像。
3. 校验 Namespace、资源类型、操作范围、凭证和高权限集群资源；失败则不执行写入。
4. 获取由 Cluster ID、Namespace 和应用实例组成的锁，锁内复核权限。
5. 执行 Helm upgrade/install 或 kubectl apply；按资源类型检查完成/就绪条件。
6. 保存实际配置版本、镜像 Digest、资源关联、清单/inventory、执行和验证结果、日志引用。

**规则**：生产凭证只投影给受信任 CD Task；目标失联、写入超时或锁超时必须核实旧执行和目标状态，未确认停止前禁止重发；部署失败保留已经发生的目标变化。

**验收标准**：

- Given Helm OCI Chart、Git YAML、Git Kustomize 各有固定版本，When 发布，Then 三类来源均能完成获取、渲染、部署和就绪检查。
- Given 清单包含未经授权的集群级资源，When 渲染校验，Then 在写入前失败。
- Given 目标 API 写入结果未知，When Controller 恢复，Then 先核实原执行和目标状态，不创建第二个写入者。

#### 6.4.4 部署结果、历史与重新发布

**需求描述**：用户查看应用实例当前确认版本、每次 DeploymentRun 的结果和历史，并可对保留的旧版本发起新的受控运行。

**交互流程**：

1. 在 Application 详情查看按 Application UID、Cluster UID、Namespace 和实例名归并的部署历史。
2. 打开运行查看配置/包版本、业务镜像 Digest、Target、资源清单、阶段结果、观察时间和日志。
3. 选择历史快照点击“重新发布”；系统重新鉴权，创建新的 DeploymentRun，不修改原记录。
4. 当前实例状态只采用已确认写入结果；未知/部分失败显示异常，不能用上一条成功记录掩盖后续失败。

**验收标准**：

- Given 历史运行已保留，When 重新发布旧版本，Then 创建新 DeploymentRun 并重新检查当前权限。
- Given 最近一次部署部分失败，When 查询实例状态，Then 显示异常和最后观察时间，不显示为上一版本成功。
- Given 用户只能查看历史，When 点击重新发布，Then 操作不可用且 API 返回无权限。

## 七、非功能性需求

| 类别 | 要求 | 验证方式 |
| --- | --- | --- |
| 权限 | 列表、详情、日志、结果、制品下载和游标查询均服务端鉴权；不能以客户端过滤器代替权限 | 角色矩阵和越权测试 |
| 安全 | 凭证明文仅存在受管 Secret/密钥服务；快照、日志、结果、审计和 API 响应不含密钥 | 脱敏扫描、渗透和日志检查 |
| 稳定性 | Controller 重启、Runner 失联、Global 暂不可用时保留状态、最后观察时间和可恢复关联 | 故障注入和恢复测试 |
| 可追溯性 | PipelineRun/DeploymentRun 保存不可变输入、稳定 UID、Commit/Digest、目标、主体和原生执行引用 | 快照与历史核对 |
| 一致性 | 请求、原生下发、状态同步、归档、清理和 Webhook 均支持幂等；未知状态不得重放 | 重复请求和断点恢复测试 |
| 可用性 | 核心页面明确显示权限不足、排队、采集延迟、失败阶段和重试入口；不展示无法证明的成功状态 | 可用性走查 |
| 性能 | API 响应、并发、日志延迟、历史查询和可用性目标待确认 | 冻结指标后执行性能测试 |

## 八、依赖、假设与风险

### 8.1 关键依赖

- Nexus ResourceNode、Policy、角色动作、资源登记、列表过滤和撤权生效接口。
- Global 服务包、集群稳定 ID、跨集群访问通道、安装状态回传和离线仓库协议。
- Tekton Pipeline/Webhook/Resolver/Results/Watcher、Vector、Harbor、PostgreSQL、OpenSearch 的支持版本。
- 受信任模板、Task Bundle、工具镜像、扫描数据库、Chart 和 Git 仓库资产。
- Target 集群 Namespace、最小权限部署凭证和业务镜像拉取凭证。

### 8.2 假设

- “本期”作为 MVP 版本范围；正式版本号、上线日期和负责人待确认。
- Global 提供可信租户/用户上下文，客户端不能伪造 Tenant、节点、Namespace、执行身份或授权结果。
- 生产部署审批、持续健康和自动回滚不属于本期；若业务确认必须纳入，需重新评估范围和里程碑。
- 应用部署允许的资源类型、就绪判定和参数白名单由服务端策略提供，不由用户在请求中任意扩大。

### 8.3 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- |
| IAM 资源引用和撤权契约未统一 | 越权或历史不可查 | 高 | 需求冻结前完成 API/UID/缓存失效联调；以拒绝优先验收 |
| Runner/Target 稳定 ID 或安装回传不完整 | 重复执行、错误关联 | 中 | 固定 UID、对象名称和核对流程；结果未知禁止重发 |
| 模板/工具镜像版本漂移 | 构建不可复现 | 中 | Bundle、镜像、Chart 全部固定 Digest；发布清单校验 |
| 日志或 Results 归档延迟/丢失 | 运行不可诊断 | 中 | 显示采集状态和缺口；归档未完成禁止清理 |
| 部署写入超时或外部副作用 | 重复部署或部分变更 | 中 | 目标锁、状态核对、保留部分失败结果；不提供自动回滚 |
| 离线资产不完整 | 客户无法完成主路径 | 中 | 安装前资产清单校验和离线 E2E |
| 性能/SLO 未冻结 | 无法判定上线质量 | 高 | 在开发完成前补齐并纳入性能门槛 |

### 8.4 待澄清问题

1. 正式版本号、开发/联调/测试/上线日期和各阶段负责人是什么？
2. API P95/P99、最大并发、可用性、错误率、日志延迟和历史保留目标是什么？
3. Nexus 对 ResourceNode 子树展开、资源 UID 登记、历史授权锚点和撤权即时性的最终接口是什么？
4. 非 CR 模板资产如何登记到 IAM，平台模板发布者的角色和审计接口是什么？
5. Global 包协议、集群稳定 ID、安装状态回传和跨集群访问通道何时冻结？
6. 支持的 Tekton、Results、Vector、Harbor、Kubernetes、Helm、Kustomize 版本矩阵是什么？
7. 历史、日志、制品、镜像、Chart 和审计的保留周期与删除责任人是什么？
8. 生产部署是否需要审批；若需要，审批主体、超时和拒绝状态如何进入 DeploymentRun？
9. 支持的浏览器、图形编辑器兼容范围、最大 Stage/Task 数和 YAML 大小上限是什么？
10. 部署失败、数据库迁移和外部副作用发生后，运营和研发的人工处置流程是什么？

## 九、测试与验收计划

### 9.1 测试范围

- **功能测试**：服务启停、Runner、构建池、部署池、模板、Pipeline、Application、运行和历史。
- **权限测试**：角色组合、跨项目/租户隔离、资源引用、日志/制品下载、撤权和审计。
- **异常恢复**：重复请求、Webhook 重放、容量不足、Runner/Target 失联、下发超时、Controller 重启、归档失败、日志缺口。
- **交付测试**：Helm OCI、Git YAML、Git Kustomize；默认版本、版本覆盖、镜像 Digest、目标锁、就绪检查和重新发布。
- **兼容与离线**：支持矩阵、升级/回滚、无公网资产、内网 CA、内网 Harbor 和依赖源。
